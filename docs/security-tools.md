# Security Tools and Triage Process

## Обзор

В проекте используются три взаимодополняющих security-инструмента:

| Инструмент | Категория | Объект анализа |
|---|---|---|
| Bandit | SAST | Собственный Python-код |
| Gitleaks | Secret scanning | Файлы проекта и Git-история |
| pip-audit | SCA | Сторонние Python-зависимости |

Один инструмент не заменяет другой:

- Bandit не проверяет утечки секретов и CVE библиотек;
- Gitleaks не определяет небезопасную бизнес-логику;
- `pip-audit` не анализирует собственный исходный код.

---

## Bandit — SAST

### Что проверяет

Bandit анализирует Python-код без запуска приложения. Такой подход называется Static Application Security Testing — SAST.

Он ищет потенциально небезопасные конструкции, включая:

- `eval()` и подобные динамические вызовы;
- небезопасную десериализацию;
- небезопасное использование `subprocess`;
- слабые криптографические алгоритмы;
- hardcoded password patterns;
- другие известные рискованные паттерны Python.

### Локальный запуск

```bash
python -m bandit -r app -f json -o reports/bandit-report.json
```

### Как обрабатывать находку

1. Определить, где и при каких условиях вызывается код.
2. Оценить, контролируется ли входное значение пользователем.
3. Исправить рискованный код безопасной альтернативой.
4. Запустить тесты и Bandit повторно.
5. Если находка — false positive, задокументировать обоснование исключения.

SAST-находка показывает потенциальный риск, но не всегда автоматически доказывает, что уязвимость эксплуатируема.

## Gitleaks — поиск секретов

### Что проверяет

Gitleaks ищет признаки чувствительных данных:

- API keys;
- access tokens;
- пароли;
- private keys;
- cloud credentials;
- секреты, соответствующие известным шаблонам.

Он может проверять не только текущие файлы, но и историю Git-коммитов.

### Локальный запуск

```bash
gitleaks detect --source . --no-git --report-format json --report-path reports/gitleaks-report.json
```

В GitHub Actions проверка выполняется с полной Git-историей.

### Как действовать при находке

1. Сразу удалить секрет из рабочего кода и конфигурационных файлов.
2. Считать секрет скомпрометированным.
3. Отозвать или ротировать значение у провайдера.
4. Перенести новое значение в безопасное хранилище, например GitHub Secrets.
5. Проверить Git-историю и выполнить новый security scan.

Удаление секрета только из последнего commit не делает его безопасным: старое значение может остаться в истории Git.

В демонстрационных сценариях допустимо использовать только искусственные тестовые значения, никогда — рабочие ключи или пароли.

## pip-audit — SCA

### Что проверяет

`pip-audit` относится к Software Composition Analysis (SCA). Он сопоставляет версии Python-зависимостей с базами известных vulnerabilities и advisory.

Проверяются:

- прямые зависимости из `requirements.txt`;
- транзитивные зависимости, которые устанавливаются вместе с ними.

### Локальный запуск

```bash
python -m pip_audit -r requirements.txt -f json -o reports/pip-audit-report.json
```

### Как действовать при находке

1. Определить затронутый пакет, версию и advisory.
2. Проверить, есть ли исправленная версия.
3. Обновить зависимость в допустимом диапазоне версий.
4. Повторно установить зависимости.
5. Запустить тесты, `pip-audit` и Docker build.
6. Если обновление невозможно, документировать риск, компенсирующие меры и срок пересмотра исключения.

Наличие CVE не означает, что она автоматически эксплуатируема в конкретном приложении. Необходима оценка контекста: используется ли уязвимый функционал, доступен ли он извне и есть ли компенсирующие меры.

## Упрощённая политика v1

Для учебного проекта действует строгая политика:

| Инструмент | Условие блокировки |
|---|---|
| pytest | Любой упавший тест |
| Bandit | Любая находка по текущей конфигурации |
| Gitleaks | Любая потенциальная утечка секрета |
| pip-audit | Любая известная уязвимость зависимости |
| Docker build | Невозможность собрать image |

В production-среде правила часто зависят от критичности сервиса, CVSS, эксплуатируемости, доступности исправления и утверждённого процесса risk acceptance.
