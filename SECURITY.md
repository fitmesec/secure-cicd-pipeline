# Security Policy

## Supported Version

Этот репозиторий является учебным проектом. Поддерживается текущая версия кода в ветке `main`.

## Reporting a Security Issue

Если вы обнаружили потенциальную security-проблему в этом репозитории:

1. Не публикуйте рабочий exploit, настоящий секрет или чувствительные данные в публичном Issue.
2. Создайте GitHub Issue с минимальным безопасным описанием проблемы.
3. Не включайте в Issue токены, пароли, API-ключи, private keys или персональные данные.
4. Укажите:
   - краткое описание;
   - затронутый файл или компонент;
   - возможное влияние;
   - безопасные шаги воспроизведения;
   - возможный способ исправления, если он известен.

## Handling Secrets

Если секрет был случайно добавлен в Git-историю:

1. Считайте его скомпрометированным.
2. Немедленно отзовите или ротируйте значение у соответствующего провайдера.
3. Удалите секрет из исходного кода и конфигурационных файлов.
4. Перенесите конфигурацию в переменные окружения или GitHub Secrets.
5. Проверьте историю Git и повторно запустите Gitleaks.

Удаление секрета из последнего commit недостаточно, если секрет уже был опубликован в истории.

## Automated Security Checks

В GitHub Actions workflow запускаются:

- `pytest` — проверка поведения приложения;
- Bandit — SAST-анализ Python-кода;
- Gitleaks — поиск потенциальных секретов;
- `pip-audit` — проверка известных уязвимостей зависимостей;
- Docker build — проверка воспроизводимой сборки приложения.

Автоматические проверки помогают находить типовые проблемы, но не заменяют ручной code review, threat modeling и контекстный анализ результатов.
